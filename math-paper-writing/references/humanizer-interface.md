# Humanizer interface

Read and apply the available original Humanizer to drafted or revised manuscript prose before delivery, even when no defect is apparent. Retention is valid. It is an optional installation dependency: if unavailable, use the writing skill's guidance and disclose the fallback; do not claim an unread skill ran.

The entrypoint's version-checked rule view is an allowed reading route: rules, false-positive guidance and invocation procedure stay verbatim; reviewed illustrations are available on demand. Read ambiguous examples before editing. An unrecognized source revision requires the original text. Do not call the view a full-file read.

## Authority order

User scope and accepted author choices, repository policy, mathematical meaning, evidence and checked citations take precedence over optional profiles and stylistic preferences. Preserve necessary qualifications without weakening established results.

## Coordinate editing stages

Mathematical writing owns manuscript content and proof-bearing edits; the study skill owns teaching content. For structural work, finish [information selection](exposition-and-structure.md#select-information-and-integrate-revisions) first. Apply anti-defensive review, then hand Humanizer the selected text, retained claims, audience and locked structure. Its claim-preservation rule applies to this handoff, not every earlier draft. Paragraph merging/splitting is allowed within scope; discarding claims is not a substitute for content selection.

If cleanup exposes a substantive or structural issue, return it to the owning stage and refresh the affected handoff. Do not cycle cleaners until they agree. Use lieflat only for explicit whitelist matches after structure is settled; its narrower paragraph-order rule and Chinese triggers do not authorize broader English editing. It is not an additional default pass, including in mathematical DNA application.

## Default scope

Review all prose within the requested scope, including proofs. Humanizer may edit non-proof-bearing exposition: abstracts, introductions, motivation, related work, transitions, remarks and conclusions. Formal statements, proof-bearing steps/computations, formulas, bibliography and evidence notices remain locked to cleanup. Locks restrict edits, not inspection: return findings to mathematical writing. Explicitly authorized editing within these regions requires the semantic audit below.

## Protected tokens and structures

Preserve commands, environments, delimiters, comments, labels, references, citation keys, notation, indices, parameter ranges, quantifiers and equation numbers. Preserve source titles, names, quotes, user terminology and evidence qualifications. Style preferences do not override mathematical minus signs, LaTeX double hyphens, ranges or conventional compounds such as `Faber--Krahn`.

## Controlled pipeline

1. Establish the selected passage's claims, assumptions, exceptions, terminology, status, citations and protected tokens in working context. Reuse this contract across both language reviews; no duplicate ledger is needed.
2. Apply original Humanizer in embedded mode to this passage, requesting revised prose only, with its audience and authorized scope. Add no fact, citation, example or interpretation.
3. Compare with the handoff: check qualifiers, quantifiers, negation, logical relations, claimed strength, notation, evidence and LaTeX. Restore or repair unsafe spans under mathematical writing rules.
4. Read changed prose with its neighbors and the next use; perform the final required build after edits. Use the shared delivery checks rather than rebuilding separately after each language review.

## Style goals for mathematical prose

Remove inflated significance, vague attribution, empty transitions, repetitive templates and chatbot correspondence. Preserve the mathematical register, useful repetition, precise terms and conventional passive constructions. A recognizable pattern prompts inspection; it is not permission to delete useful explanation or inject personality into a theorem.

## Handoff record

The main skill's single delivery note records actual review scope, one concrete retained/revised example and semantic read-back. Loading instructions alone is not execution evidence and does not upgrade mathematical status.
